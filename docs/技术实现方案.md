# 影跟读 · 技术实现方案

> 版本：v0.1（初稿）
> 日期：2026-11-07
> 范围：中/英影子跟读小程序 MVP 到可运营版本的架构设计

---

## 1. 目标与需求拆解

### 1.1 产品目标

用户粘贴一个视频链接或上传本地视频 → 一键导入 → 自动提取文案并分句 → **播放原视频**、**查看完整文案**、**任选一句影子跟读**（听原声 / 录音 / 回放对比）。

### 1.2 功能拆解

| 模块 | 功能点 | 难度 | 说明 |
|---|---|---|---|
| 输入 | 粘贴抖音/微信等链接 **或上传本地视频** | 中 | 链接形态多、需解析真实媒体地址；上传作为兜底 |
| 下载 | 一键下载视频/音频 | 高 | 各大平台反爬、视频号基本不可行（见风险） |
| 视频播放 | **原视频播放（整段）** | 中 | 链接视频与上传视频都要能播放，需保留/转码原视频 |
| 文案提取 | 语音转文字（ASR） | 中 | 需带时间戳，才能对齐音视频 |
| 全文 | **查看完整文案，任意句可点选** | 低 | 逐句分段展示，点任一句进入跟读 |
| 分句 | 按段落/标点切成一句句 | 中 | 依赖 ASR 时间戳 + 文本后处理 |
| 跟读 | **任选一句**播放原文（音频/视频片段） | 中 | 单句视频 `seek → end` 或预切片段 |
| 录音 | 跟读录音、结束、回放 | 中 | 小程序录音权限与格式 |
| 对比 | 用户录音 vs 原文 | 中 | **第一版只做 A/B 回放，不做发音评分** |

### 1.3 两个必须先确认的产品假设

1. **"小程序"形态**：本方案默认按 **微信小程序** 设计（免安装、包体小、易传播），同时用跨端框架保留 App/H5 能力。若目标是独立 App，见 §3 选型对比。
2. **"微信视频"含义**：
   - 微信聊天/朋友圈里转发的 **普通 mp4 文件** → 可解析/可上传，支持。
   - **视频号（Channels）内容** → 有强版权与 DRM 保护，技术上**基本无法合规下载**，本方案不承诺支持，提供"本地文件上传"作为兜底（见 §10 风险）。

## 2. 核心设计原则

1. **客户端做薄，服务端做重**：下载、转码、ASR、切句、切片全部在服务端完成。客户端只负责"提交链接 / 播放 / 录音 / 上传"。这是控制安装包体积的关键。
2. **异步任务化**：下载 + ASR 是秒级到分钟级的长任务，必须用任务队列 + 进度轮询/推送，不能同步阻塞。
3. **音视频双支持**：原视频必须可播放（链接视频与上传视频均支持）；句子跟读以"音频片段"为主、视频片段为辅，整段与单句都能在视频/音频两种模式下切换。查看全文、任选一句是核心交互，不能只做顺序播放。
4. **可降级**：云端 ASR 不可用时能切自建 Whisper；链接解析失败时能退回"本地上传文件"。
5. **合规优先**：只处理用户有权使用的内容，明确版权与平台条款边界。

## 3. 客户端形态选型

| 方案 | 包体 | 录音能力 | 视频播放 | 开发成本 | 结论 |
|---|---|---|---|---|---|
| **微信小程序** | 主包 ≤2MB，分包后可到 ~20MB | ✅ RecorderManager | ✅ video 组件 | 低 | **推荐**，最契合"免安装 + 包体小 + 易传播" |
| uni-app（一套代码多端） | 小程序同左；App ~20MB+ | ✅ | ✅ | 中 | **推荐框架**，后续可出 App/H5 |
| 原生 App（Flutter/RN） | 20–50MB | ✅ | ✅ | 高 | 包体大、需安装，与"包体小"目标冲突 |
| 纯 H5 | 0 | ⚠️ iOS Safari 限制多 | ✅ | 低 | 仅作分享落地页，不作主形态 |

> **决策**：用 **uni-app（Vue3）** 开发，主发布微信小程序；后续需要时一键出 H5/App。所有重逻辑放服务端，客户端不打包任何媒体处理库（不打包 ffmpeg / Whisper）。

### 包体控制手段

- 主包只放首页 + 通用组件；跟读详情页放**分包**。
- 音频/视频全部走 **CDN + 签名 URL**，不打包进包。
- 图标用字体图标/雪碧图；大图走 CDN。
- 不在客户端做音视频转码、ASR、评分。

### 组件职责

- **客户端**：交互、播放、录音、上传、进度展示。
- **API 服务（FastAPI）**：鉴权、任务创建/查询、句子与录音 CRUD、签名 URL 下发。
- **任务队列（Celery/Redis）**：串起"解析→下载→抽取→ASR→分句→切片"流水线。
- **媒体 Worker**：yt-dlp + ffmpeg + ASR，独立容器，可水平扩容，可挂 GPU。
- **存储**：DB 存结构化数据；OSS 存原始媒体/音频/切片/录音；CDN 加速播放。

## 5. 核心链路时序

```
① 用户粘贴链接，点"一键下载"
② 小程序 → POST /tasks {url}；API 创建 Project(status=queued)，立即返回 taskId
③ 小程序轮询 GET /tasks/{id} 获取进度
④ Worker：yt-dlp 解析并下载视频
⑤ Worker：ffmpeg 抽取 16k 单声道音频
⑥ Worker → 云 ASR：请求带时间戳转写
⑦ ASR → Worker：返回 文本段 + start/end
⑧ Worker：按规则分句，并逐句 ffmpeg 切片
⑨ Worker：上传音频/切片到 OSS，更新 Project(status=ready)
⑩ 小程序拉取句子列表（文本 + 时间 + 切片签名 URL）
⑪ 用户点某句 → 详情页，CDN 播放原句
⑫ 用户录音开始/结束 → 上传录音 →（可选）发音评测
⑬ 小程序 A/B 回放，完成对比
```

## 6. 各模块详细设计

### 6.1 链接解析与下载

**统一解析层（`resolver` 抽象）**，按域名分发：

| 来源 | 做法 | 可行性 |
|---|---|---|
| 抖音 | 分享口令/短链 `v.douyin.com/xxx` → 跟随 302 → 取 `aweme_id` → 调用去水印解析接口取直链 | 中（反爬变化频繁，需持续维护） |
| 微信普通视频 | 用户直接**上传文件**；或解析转发链接拿到 mp4 | 中 |
| 视频号 | 不做，提示"暂不支持，请上传本地文件" | 不可行 |
| B站/其他 | yt-dlp 原生支持 | 高 |

- 用 `yt-dlp` 做通用下载器，平台专用解析器作为前置（拿到直链后交给 yt-dlp 或直接 download）。
- Worker 内装 `yt-dlp`，定期升级（反爬策略变动快）。
- 下载超时、大小上限（如 ≤300MB）、并发限流。
- **存储策略**：为支持原视频播放，**必须保留原始视频**（或转码后的统一 mp4），不能只留音频。默认保留期可配置（如 30 天 / 用户主动删除即删）；为降成本可将长期未访问的内容转低频存储，到期清理后降级为"仅音频跟读"并提示用户。

### 6.2 音频提取

```
ffmpeg -i input.mp4 -vn -ac 1 -ar 16000 -f wav audio.wav   # 给 ASR
ffmpeg -i input.mp4 -vn -b:a 64k audio.mp3              # 给前端整段播放
```

- 统一 16k 单声道 WAV 供 ASR；64k mp3 供播放。
- 时长上限保护（如 ≤30 分钟，避免 ASR 成本失控）。

### 6.3 文案提取（ASR，带时间戳）

**核心诉求：文本 + 每段 start/end 时间戳**（分句和切片的依据）。

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| 云 ASR（火山/腾讯/阿里/讯飞，录音文件识别） | 免运维、快、中英识别好、自带时间戳 | 按分钟计费 | **MVP 首选（当前：火山豆包）** |
| 自建 faster-whisper (large-v3) | 无按次成本、离线 | 需 GPU/CPU 较慢、要运维 | 量上来后切换 |
| WhisperX（强制对齐） | 词级时间戳更准 | 更重 | 对英文跟读高要求时用 |

**推荐策略**：MVP 用云 ASR；当"分钟数 × 单价"超过自建 GPU 成本时切 faster-whisper，接口层抽象 `ASRProvider` 便于切换。

### 6.4 分句算法（关键）

输入：ASR 段落（text, start, end）。输出：一句一条 `Segment`。

规则：
1. 按中英文标点 `。！？!?；;\n` 切分。
2. 无标点时按 **最大时长**（如 15s）和 **最大字数**（中 ~40 字 / 英 ~25 词）切分。
3. 合并过短片段（< 1s 或 < 3 字）。
4. 保留每句 `start_ms / end_ms`（用词的起止时间戳做边界）。
5. 英文用词级时间戳对齐，中文按字符时间戳近似。

### 6.5 切片与存储

- **start/end 从哪来**：ASR 返回的**句级/词级时间戳**（见 §6.3）。分句时把每句映射到对应词：`start = 首词.start`、`end = 末词.end`，前后各留 80~150ms 余量并 clamp 到 `[0, duration]`，写入 `segments.start_ms / end_ms`。若用字幕轨，则直接用 SRT/VTT 的时间戳。
- **先一次性解码，再切片**（避免对 mp3/mp4 反复解码与 seek）：
  ```bash
  # 1) 视频先解码为统一 WAV
  ffmpeg -i input.mp4 -vn -ac 1 -ar 16000 -f wav full.wav

  # 2) 按句子时间戳切片（输出定位，精确；-to 是结束时间）
  ffmpeg -i full.wav -ss 42.300 -to 47.100 -c:a libmp3lame -b:a 64k -y seg_12.mp3

  # 3) 或用输入定位 + 时长（更快；-t 是持续时长，不要与 -to 混用）
  ffmpeg -ss 42.300 -i full.wav -t 4.800 -c:a libmp3lame -b:a 64k -y seg_12.mp3

  # 4) WAV/PCM 可采样级无损裁切（极快）
  ffmpeg -ss 42.300 -i full.wav -t 4.800 -c copy seg_12.wav
  ```
- 命名：`{projectId}/segments/{index}.mp3` 存 OSS。
- 句子列表返回 CDN 签名 URL（带过期时间，防盗链）。
- 可选：整段音频 + `start/end` 让前端 `innerAudioContext.seek()` 播放，减少文件数；但**推荐预切片**，播放更稳、可缓存、便于离线。
- **原视频**：转码为 H.264 + AAC 的 mp4（或 HLS）存 OSS，支持 HTTP Range 以便 `seek`；`projects.video_url` 下发签名 URL。
- **单句视频**：MVP 不预切，前端 `videoContext.seek(start_ms)` → 播放到 `end_ms` 暂停/循环（零额外存储）；P1 可选预生成单句 mp4 供离线缓存。

### 6.6 视频播放与全文视图

- **原视频（整段）播放**：句子列表页/全文页顶部播放器，播放时按 `timeupdate` **高亮当前句并自动滚动**。
- **单句视频播放**：详情页 `videoContext.seek(start_ms)`，到 `end_ms` 自动暂停（或循环）；与音频共用同一时间轴，保证音画同步。
- **时间对齐**：ASR 的 `start_ms/end_ms` 直接作为视频切点；若需画面更准，转码时对齐 GOP/关键帧。
- **全文视图**：展示完整文案，逐句分段，**任一句可点击** → 进入该句详情或直接定位播放；支持"连续跟读"逐句自动推进。
- **降级**：视频加载失败或已过期时，自动回退为"音频 + 文本"跟读。

### 6.7 录音

- 微信 `wx.getRecorderManager()`：`format: 'mp3'`（或 aac），`sampleRate: 16000`，`numberOfChannels: 1`。
- 流程：点按开始 → 录音中（计时/波形）→ 再点结束 → 生成临时文件 → 上传 OSS（或先传 API）。
- 单句录音时长上限（如 60s）自动截断。
- 权限：首次申请麦克风，拒绝时引导设置页开启。

### 6.8 用户录音 vs 原文对比

**第一版（v1）只做 A/B 听感对比，不做发音评分。**

1. **A/B 播放（v1）**：原句 → 用户录音，顺序播放；也支持单独回放、循环。
2. **波形对比（后续）**：并排显示两条波形（小程序用 canvas 或插件绘制；H5 可用 wavesurfer.js）。
3. **发音评分（后续版本，暂不实现）**：如需，才引入评测 API（讯飞 / 腾讯 / Azure），且需要把录音上传服务端，带来成本与隐私工作。

> 结论：v1 不接评测 API、不产生评分数据；`recordings.score` 字段仅预留，不使用。

## 7. 数据模型（MySQL 8.0）

```sql
-- MySQL 8.0 / InnoDB / utf8mb4
-- 用户
users(id, openid, nickname, created_at)

-- 一次跟读项目（一个视频）
projects(
  id, user_id, source_url, source_type, title, cover_url,
  source_video_url,   -- 原始/转码后的视频（支持播放，需保留）
  video_status,       -- none/processing/ready/expired
  video_expire_at,    -- 视频保留到期时间
  status,            -- queued/parsing/downloading/transcribing/segmenting/ready/failed
  progress,          -- 0-100
  error_msg,
  duration_ms, lang, created_at, updated_at
)

-- 句子
segments(
  id, project_id, idx, text, start_ms, end_ms,
  audio_url, video_url,   -- audio_url 必有；video_url 可空(按需切片/整段seek)
  created_at
)

-- 用户录音
recordings(
  id, segment_id, user_id, audio_url,
  duration_ms, score, score_detail_json, created_at
)
```

索引：`segments(project_id, idx)`、`projects(user_id, created_at)`、`recordings(segment_id, user_id)`。

## 8. API 设计（REST）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | wx.login code → JWT |
| POST | `/api/tasks` | 提交链接，返回 `taskId`；body: `{url}` |
| POST | `/api/tasks/upload` | 上传本地音视频文件创建任务 |
| GET | `/api/tasks/{id}` | 查询状态/进度 |
| GET | `/api/projects` | 我的项目列表 |
| GET | `/api/projects/{id}` | 项目详情（含 `video_url` 播放地址） |
| GET | `/api/projects/{id}/transcript` | 完整文案 + 全部句子（全文视图用） |
| GET | `/api/projects/{id}/segments` | 句子列表（含音频切片、`start/end`、视频 seek 信息） |
| GET | `/api/projects/{id}/video` | 原视频播放地址（签名 URL / HLS manifest） |
| POST | `/api/segments/{id}/recordings` | 上传录音（multipart），返回 `recordingId` |
| POST | `/api/segments/{id}/score` | 发音评测（**v1 不实现，预留**） |
| GET | `/api/recordings/{id}` | 录音详情/回放 URL |

- 鉴权：JWT；签名 URL 有效期 1h。
- 进度：短任务轮询（1–2s）；长任务可加 WebSocket/SSE，但小程序 MVP 用轮询即可。

**跟读详情页布局（对应需求）**

```
┌─────────────────────────────┐

│                             │
│  [视频/音频片段区域]          │
```

交互细节：
- 原声播放与录音互斥（录音时暂停原声）。
- 录音按钮状态机：`idle → recording → hasRecording(可播放)`；再次录音覆盖。
- 句子列表页支持"整段播放 + 高亮当前句"，模仿跟读时自动滚动定位。
- **全文视图**：完整文案逐句展示，任一句可点击跳转；当前播放句高亮。
- **视频/音频切换**：详情页可切换"看视频"或"只听得清"的音频模式，视频不可用时自动降级音频。
- 支持循环/慢放（0.75x/0.5x）——影子跟读常用。

## 10. 技术风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **视频号无法下载** | 核心输入不可用 | 明确不支持；提供本地上传；文案说明 |
| 抖音反爬频繁变化 | 解析失败率高 | 解析器可插拔 + 定期升级 yt-dlp + 失败降级本地上传 |
| 版权/平台条款 | 合规风险 | 仅限用户自有/授权内容；不提供公开分发；隐私政策与免责声明 |
| ASR 成本 | 随用量线性上升 | 时长上限 + 按规模切换自建 Whisper |
| 小程序录音格式/权限 | iOS/安卓差异 | 统一 mp3、首次引导授权、失败兜底提示 |
| 长音频处理慢 | 用户等待焦虑 | 异步 + 进度条 + 分段转写 + 失败重试 |
| 存储成本（需保留视频） | 费用高 | 保留期可配（如 30 天）+ 低频存储 + 到期降级为仅音频；用户删除即删 |
| 发音评测接入 | 额外成本与延迟 | 作为可选增强，异步返回评分 |
