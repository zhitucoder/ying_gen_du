# 手机号短信验证码方案

> 目标：支持**手机号注册**、**手机号验证码登录**，并具备防刷、限频、验证码加固能力。
> 约束：每个手机号每天最多发送 **5 条**短信。
> 整理日期：2026-11-08（价格以官网为准）

---

## 3. 账号与流程设计

### 3.1 账号模型

在现有 `users` 表上扩展：

```sql
ALTER TABLE users ADD COLUMN phone VARCHAR(20) NULL;
ALTER TABLE users ADD COLUMN phone_verified_at DATETIME NULL;
ALTER TABLE users ADD UNIQUE KEY uk_users_phone (phone);
```

- 手机号用户：`openid = phone:<手机号>`，`auth_type = phone`，`phone_verified_at` 非空。
- 继续兼容用户名/密码登录。
- 后续可支持微信登录 `openid = wx:<openid>`。

### 3.2 注册流程

```
用户输入手机号
   → (可选) 图形验证码
   → POST /api/auth/sms/send  {phone, scene:"register"}
   → 服务端限流检查 → 生成6位码 → 存哈希 → 调短信厂商
   → 用户输入验证码
   → POST /api/auth/sms/register {phone, code, nickname?}
   → 校验码 → 手机号不存在则创建用户 → 返回 JWT
```

### 3.3 验证码登录流程

```
用户输入手机号
   → POST /api/auth/sms/send {phone, scene:"login"}
   → 用户输入验证码
   → POST /api/auth/sms/login {phone, code}
   → 校验码 → 查用户 → 返回 JWT
```

> 建议：`login` 场景下若手机号未注册，可在**验证码校验通过后**自动创建账号（登录即注册），减少流失；若产品要求区分，则返回“该手机号未注册，请先注册”。

### 3.4 绑定手机号（已登录）

```
POST /api/auth/sms/send {phone, scene:"bind"}   （需登录）
POST /api/auth/sms/bind {phone, code}            （需登录）
```

- 绑定前检查该手机号是否已被其他账号占用。
- 绑定成功后写 `phone_verified_at`。

## 4. 接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/sms/send` | 发送验证码 `{phone, scene, captcha_token?, device_id?}` |
| POST | `/api/auth/sms/register` | 手机号注册 `{phone, code, nickname?}` → JWT |
| POST | `/api/auth/sms/login` | 手机号验证码登录 `{phone, code}` → JWT |
| POST | `/api/auth/sms/bind` | 绑定手机号（需登录）`{phone, code}` |
| GET | `/api/auth/me` | 当前用户信息（含 phone） |

### 4.1 发送响应

```json
{
  "sent": true,
  "retry_after": 60,
  "expires_in": 300
}
```

- **绝不返回验证码明文**。
- 无论手机号是否已注册，统一返回“验证码已发送”，避免枚举。
- 触发限流返回 `429`，并带 `retry_after`。

### 4.2 错误码

| HTTP | detail | 场景 |
|---|---|---|
| 400 | 手机号格式不正确 | 非法手机号 |
| 429 | 发送过于频繁，请稍后再试 | 60 秒冷却 |
| 429 | 今日验证码发送次数已达上限 | 日限 5 条 |
| 403 | 需要完成图形验证 | 需要 captcha |
| 401 | 验证码错误或已过期 | 校验失败 |
| 409 | 该手机号已注册 | 注册场景重复 |
| 404 | 该手机号未注册 | 登录场景不存在 |
| 502 | 短信发送失败，请稍后重试 | 厂商故障 |

## 5. 数据模型

```sql
CREATE TABLE sms_codes (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  phone         VARCHAR(20)  NOT NULL,
  scene         VARCHAR(16)  NOT NULL,        -- register / login / bind
  code_hash     VARCHAR(255) NOT NULL,        -- 只存哈希，不存明文
  expires_at    DATETIME     NOT NULL,
  attempts      INT          NOT NULL DEFAULT 0,
  used_at       DATETIME     NULL,
  request_ip    VARCHAR(64)  NULL,
  device_id     VARCHAR(64)  NULL,
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_phone_scene_created (phone, scene, created_at),
  KEY idx_expires (expires_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE sms_send_logs (
  id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  phone           VARCHAR(20)  NOT NULL,      -- 日志中脱敏
  scene           VARCHAR(16)  NOT NULL,
  provider        VARCHAR(16)  NOT NULL,      -- aliyun / tencent / yunpian / mock
  provider_msg_id VARCHAR(64)  NULL,
  status          VARCHAR(16)  NOT NULL,      -- sent / failed / blocked
  error_code      VARCHAR(64)  NULL,
  request_ip      VARCHAR(64)  NULL,
  device_id       VARCHAR(64)  NULL,
  created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_phone_created (phone, created_at),
  KEY idx_ip_created (request_ip, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 6. Redis 限流键

> 限流用 Redis（原子 `INCR`/`SET NX`），审计用 MySQL。

| Key | 类型 / TTL | 作用 |
|---|---|---|
| `sms:cd:{scene}:{phone}` | String, 60s | 60 秒冷却 |
| `sms:day:{phone}:{yyyymmdd}` | Counter, 25h | 单手机号每日 5 条 |
| `sms:hour:{phone}:{yyyymmddHH}` | Counter, 2h | 单手机号每小时 3 条 |
| `sms:ip:hour:{ip}:{yyyymmddHH}` | Counter, 2h | 单 IP 每小时 10 条 |
| `sms:ip:day:{ip}:{yyyymmdd}` | Counter, 25h | 单 IP 每日 30 条 |
| `sms:dev:day:{device}:{yyyymmdd}` | Counter, 25h | 单设备每日 5 条 |
| `sms:lock:{phone}:{scene}` | String, 10s | 并发发送锁 |
| `sms:attempts:{phone}:{scene}` | Counter, 300s | 校验失败次数 |

**并发安全**：发送前用 Lua 脚本一次性完成冷却 + 日/时/设备/ IP 计数检查与自增，避免“先查后写”竞态。

## 7. 防刷与限流策略（五层）

1. **单手机号**
   - 60 秒冷却（同 scene）。
   - 每小时 ≤ 3 条。
   - **每天 ≤ 5 条**（自然日，Asia/Shanghai）。
2. **单 IP**
   - 每小时 ≤ 10 条，每天 ≤ 30 条。
   - 云厂商/机房 IP、代理 IP 直接拒绝或要求 captcha。
3. **单设备**
   - `device_id`（前端生成并持久化）每天 ≤ 5 条。
   - 设备指纹异常（频繁清空、模拟器）降权。
4. **图形验证码**
   - 每个发送请求都带 `captcha_token`（推荐），或至少在第 2 次发送后强制。
   - 可用腾讯云验证码/阿里云验证码/极验；自研滑块成本更高。
5. **厂商防盗刷 + 预算**
   - 开启阿里云“短信防盗刷”/腾讯云“防刷”能力。
   - 设置日预算/发送量告警、异常号码黑名单、全局熔断开关 `SMS_ENABLED=false`。

> 关键：只做“单手机号 5 条/天”挡不住换号轰炸，**IP + 设备 + 图形验证码**必须一起上。

## 8. 验证码安全加固

| 项 | 做法 |
|---|---|
| 生成 | `secrets.randbelow(1_000_000)`，补零成 6 位；禁止 `random` |
| 存储 | 只存 `HMAC-SHA256(server_secret, phone + code + salt)`，不存明文 |
| 比较 | `hmac.compare_digest` 常量时间比较 |
| 有效期 | 300 秒 |
| 一次性 | 校验成功后 `used_at` 置位，立即失效 |
| 试错 | 最多 5 次，超过即作废 |
| 重发 | 新验证码生成后，旧码立即失效 |
| 日志 | 不记录验证码；手机号脱敏为 `138****1234` |
| 响应 | 任何接口都不返回验证码 |
| 枚举 | 发送接口统一返回“已发送”；仅在验证码正确后才提示手机号是否已注册 |
| 防重放 | 验证码与 phone+scene 绑定，不能跨场景使用 |
| 防并发 | Redis 锁 + DB 事务 |
| 防遍历 | 校验接口按 phone+IP 限流（如 10 次/小时） |

### 8.1 校验逻辑（伪代码）

```python
def verify_code(phone, scene, code, db, redis):
    if redis.incr_with_ttl(f"sms:attempts:{phone}:{scene}", ttl=300) > 5:
        raise TooManyAttempts

    record = db.latest_unused_code(phone, scene)
    if not record or record.expires_at < now():
        raise InvalidCode
    if record.attempts >= 5:
        raise TooManyAttempts
    if not hmac.compare_digest(record.code_hash, hash_code(phone, code)):
        db.increment_attempts(record)
        raise InvalidCode

    db.mark_used(record)
    return True
```

## 10. 异常与幂等

- **厂商失败**：返回 `502`，记录 `sms_send_logs`；本次仍计入日限（防止失败重试刷量）。
- **重复请求**：冷却期内直接 `429`，不重复调用厂商。
- **支付/网络超时**：厂商 SDK 设 3–5 秒超时；不要无限重试。
- **幂等键**：可用 `phone+scene+60s` 作为去重键。
- **回调**：接收厂商回执，更新 `sms_send_logs.status`；失败回执可按厂商规则退费。
- **熔断**：失败率 > 20% 或日预算超限时自动关闭发送，仅记录日志并告警。

## 11. 合规与隐私

- 企业实名 + 签名/模板报备；不得发送营销内容到验证码模板。
- 隐私政策明确收集手机号用途；注册页勾选同意。
- 日志中手机号脱敏；数据库访问权限最小化。
- 保留发送/校验审计日志（建议 ≥ 6 个月）。
- 防骚扰/防诈骗：异常高频号码、投诉号码加入黑名单。
- 遵守《个人信息保护法》《通信短信息服务管理规定》。

## 14. 测试用例

- 60 秒内重复发送 → 429。
- 同手机号第 6 次/天 → 429。
- 同 IP 高频 → 429。
- 验证码错误 5 次 → 作废。
- 验证码过期（>5 分钟）→ 401。
- 验证码使用后再次提交 → 401。
- 重发后旧验证码 → 失效。
- 并发发送同一手机号 → 只成功一条。
- 注册已存在手机号（验证码正确后）→ 409。
- 登录未注册手机号 → 404（或按产品选择自动注册）。
- 厂商故障 → 502，且不泄漏内部错误。
- 日志中不出现验证码明文。
